# 设计思路

本文记录“为什么这样设计”。代码会变，这里的判断是这套能力的根。

## 1. 问题

让虚拟角色有情绪，常见做法是三件套：**关键词表 → 预设 → 优先级**。它们能跑，但都有同一个毛病：

- 关键词只认字面：“我才不生气”会被判成生气；“没事”会被判成开心。
- 预设是单选：要么开心，要么难过；做不出“有点开心但确实累了”。
- 优先级是硬约束：某类来源一响就压下别的来源，结果表情是被“规定”出来的，不是被“理解”出来的。

这三件事合在一起，恰好与真实情绪相反：真实情绪是**混合的、有上下文的、有惯性的、有时没有的**。

## 2. 核心思想：换一个来源

真正读过这段对话的，是正在生成回复的那个模型。它知道上一句是什么、用户语气如何、自己在克制还是在开玩笑。

所以：

> 情绪的**判断**应该由这个模型自己完成；系统要做的是给它一条**结构化自述**的通道，并把自述可靠地翻译成五官。

关键词/分类器都不该是主判据——它们拿不到上下文，只是对文本的二次猜测。

## 3. 四层

```text
L0 证据     FeelRequest{labels, intensity, confidence, note}
             + 任何其它来源（tag / keyword / context / classifier / manual）
L1 融合     每条证据 = 一票；权重 = 置信度 × 来源可靠性 × 新鲜度
             不做排序；冲突保留为混合；只有 manual 可以硬覆盖
L2 状态     一个连续 AffectState：labels / intensity / confidence / valence / arousal
L3 合成     标签加权 -> 眉眼 / 眼神 / 嘴角 / 脸颊 / 头部 同步变化
             （嘴型开合不属于本层，归语音层）
L4 适配     输出目标值；由调用方映射到自己的渲染器
```

## 4. 关键决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | 没有优先级阶梯，`tool`（AI 自述）权重最高（1.0），必须以它为主；唯一硬覆盖是 `manual`（用户指令），6 秒后过期 | 自述是唯一读过对话的来源；优先级会让情绪变成“被规定的”；用户指令是唯一合法的强制 |
| D1b | `manual` 不算投票来源 | 它是命令，不是证据；不参与加权，避免把“要求”混进“感受” |
| D2 | 标签是权重字典，允许混合、低置信度、空 | “自由”要求：允许犹豫、克制、无情绪 |
| D3 | 中性基线用模型真实中性值（如 smile 0.50），不是 0 | 0 会让模型撇嘴、塌眉；0 不是“没有情绪” |
| D4 | 未知标签（如 tired）贡献中性基线，而不是 0 | 混合时不该把脸拽向极端 |
| D5 | 证据权重 = confidence × 来源可靠性 × 新鲜度 | 让“确信的、近的、可靠来源”自然占优，而不是靠等级 |
| D6 | 证据 10 秒过期；状态保持 2 秒后按 2.2 秒衰减 | 防止“一直笑”；情绪要有惯性也要会退 |
| D7 | 标签变化 < 0.15 时沿用旧值 | 帧级抖动会显得假 |
| D8 | 只输出目标值，不写任何渲染器 | 核心能力必须独立于 VTS/Live2D 存续 |

## 5. 调用方必须做的两件事（当前缺口）

这两条不在库里，而在集成侧，但直接决定“自由/真实”能不能成立：

1. **系统提示引导**：告诉模型“回复前用这条通道写下当前情绪，允许混合和不确定”。不引导，模型不会主动调用，通道等于不存在。
2. **跨轮状态回灌**：把当前状态摘要（主导标签、强度、距上次变化多久）喂回下一轮。否则每轮独立判断，连续对话会忽高忽低。

## 6. 非目标

- 不做本地情绪分类器的主判据（最多低权重兜底）；
- 不做优先级系统；
- 不训练/微调模型；
- 不写渲染器，不绑定 VTube Studio；
- 不追求“识别情绪准确率”——追求的是**表达是否真实、协调、不僵**。

## 7. 验收

- 五种主情绪可区分，混合情绪不穿帮；
- 说话时表情不压嘴型；
- 情绪有惯性，10 轮对话不来回跳；
- 长待机不机械重复；
- AI 说“有点难过”时，脸不能是大笑。
